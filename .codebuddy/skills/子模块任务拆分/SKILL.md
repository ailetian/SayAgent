# 子模块任务拆分 SOP

将已规划好的大模块（Mn）拆成可逐条验收的子任务文档，沉淀到 `plans/Mn/` 目录。
颗粒度对齐标杆 `plans/M1/`，复杂模块可参考 `plans/M2/T5_*`。

## 何时使用
- 用户说"拆分 M? 任务""把模块拆成子模块任务""按验收粒度拆分"。
- 模块规划（0X_Mn_*.md）已完成、准备进入编码下发的阶段。

## 必读输入材料
1. `plans/01_大模块拆分.md` —— 模块清单、依赖顺序、技术底座继承关系。
2. 该模块源文档 `plans/0X_Mn_*.md` —— 范围、关键约束、T1..Tk 任务、汇总验收点。
3. `CLAUDE.md` —— 所有硬性规范（§5 依赖、§6 各层、§7 规则、§8 测试、§9 日志）。
4. 标杆范本：`plans/M1/` 全套（00_概述 + Tn_*）；复杂模块参 `plans/M2/T5_*`。
5. 真实基础设施类清单（防臆造）：写到异常/错误码/配置类前，先 `search_file`/`search_content` 仓库确认其真实存在（如 `common/exception/BizException`、`common/exception/ErrorCode`、`GlobalExceptionHandler`）；本项目规范只允许 `BizException`+`ErrorCode`（CLAUDE.md §3.5/§7.3），**禁止凭通用脚手架习惯臆造 `AppException` / `BizCode` 等不存在的类**。

## 输出产物
在 `plans/Mn/` 目录产出：
- `00_概述.md`：模块范围一句话、技术底座继承、任务清单表（T号→目标→文档链接）、依赖顺序图、全局验收门槛、对应 CLAUDE.md 章节索引、完成里程碑。
- `Tn_名称.md`（n 从 1 起，名称用中文动宾短语，如 `T1_ModelProvider表与仓库与枚举.md`）：每个子任务一份。

## 单个 Tn 文档的强制结构（这就是"验收粒度"）
必须包含以下 8 段，顺序固定：
1. `## 大白话`：一句话/几句话讲清要干什么，非技术也能懂。
2. `## 终点画面（做完长这样）`：可观察的完成态（文件存在、能编译、能跑通）。
3. `## 交付物清单（这些文件必须存在）`：精确相对路径清单（包名/目录/文件名），每条一个文件。
4. `## 关键要点（照着做，别踩坑）`：逐条列出必须遵循的 CLAUDE.md 规则，用 `**规则名 \`§x.y\`**` 标注出处；区分 MUST 与禁止项。
5. `## 验收点（逐条勾选）`：`- [ ]` 清单，每条都是能直接验证的断言（文件存在/字段对齐/单测绿/响应不含某字段）。
6. `## 如何验证`：可复制的验证命令（如 `./gradlew test --tests ...`）。
7. `## 对应 CLAUDE.md 章节`：本任务涉及的 § 号索引。
8. `## 完成里程碑`：`- [ ]` 清单，作为该子任务"算做完"的硬门槛。

## 拆分原则
- **粒度对齐 M1**：每个 Tn 只解决一个内聚子问题；若一个 T 过大（如含 CRUD+单测+脱敏），按"建表/接口/治理/路由/日志/单测"继续切分。
- **验收点必须可执行**：每条验收点都能用命令/查文件/看响应验证，禁止"代码质量良好"这类空话。
- **强绑定 CLAUDE.md**：每条关键要点都要指到具体 § 号，禁止泛泛而谈。
- **依赖顺序明确**：在 00_概述 画出 `T1→T2→...` 依赖图，标注哪些可并行。
- **复用不重造**：明确标注复用了哪个已交付模块（如 M1 的 Result/BaseEntity、M2 的 AuthService），禁止在新模块重复造轮子。
- **符号必须落地（防臆造类名）**：凡写到具体类名/异常名/错误码名（如 `BizException(ErrorCode.XXX)`、`Result<T>`、`BaseEntity`），必须先 `search_content` 仓库核实该类/枚举**真实存在且拼写一致**；禁止套用通用模板里的 `AppException`/`BizCode` 等本仓库不存在的名字。错误码优先复用 `ErrorCode` 已有项（如 `MODEL_NOT_FOUND(1001)`），确需新增才标注"缺失则补"。

## 收尾联动
- 拆分完成后，把 `00_总体进度表.md` 中该模块行的"对应文档"列从源文档号（如 `04`）更新为本目录的 `Mn/Tn_*.md` 链接。
- 在 00_概述 的"完成里程碑"中加一条：进度表已指向本目录。

## 命名与格式约定
- 目录：`plans/Mn/`（n 与 01_大模块拆分 中的模块号一致）。
- 概述文件固定名：`00_概述.md`。
- 任务文件：`Tn_中文名称.md`，n 零不补位（T1/T2...）。
- 表格语法、复选框 `- [ ]` 必须可被 Markdown 渲染。

## 自检清单（交付前逐条确认）
- [ ] `plans/Mn/` 下存在 `00_概述.md` 与 T1..Tk 共 k+1 个文件。
- [ ] 每个 Tn 含全部 8 段，且验收点均为可执行断言。
- [ ] 关键要点都带 `§x.y` 出处。
- [ ] 00_概述 含依赖顺序图与全局验收门槛。
- [ ] 进度表该模块行已指向 `Mn/Tn_*.md`。
- [ ] 所有异常/错误码/类名引用（如 `BizException`/`ErrorCode`/`Result`）均已 `search_content` 仓库确认真实存在，无 `AppException`/`BizCode` 等臆造类（对照 CLAUDE.md §3.5/§7.3）。

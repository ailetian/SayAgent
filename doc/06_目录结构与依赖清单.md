## 2. 后端包结构（Modulith，按功能分包）

```
com.hify.hify
├── SayAgentApplication.java
│
├── common/                          # 共享内核（被业务模块依赖，禁止反向依赖业务）
│   ├── config/                      # CorsConfig, AsyncConfig(线程池), SwaggerConfig, RedisConfig, JpaConfig
│   ├── security/                    # SecurityConfig, JwtUtil, AuthFilter, CustomUserDetailsService
│   ├── exception/                   # GlobalExceptionHandler, BizException
│   ├── base/                        # BaseEntity(id/createdAt/updatedAt), BaseRepository
│   └── util/
│
├── modelprovider/                   # 模型提供商管理（对应 04 文档组件设计）
│   ├── ModelProviderController
│   ├── ModelProviderService
│   ├── ModelProviderRepository
│   ├── ModelProvider.java           # entity: 名称/类型(openai/claude/gemini/ollama)/apiKey/baseUrl/超时配置
│   ├── dto/                         # ModelProviderReq / ModelProviderResp
│   ├── client/
│   │   ├── ProviderClient.java      # 统一接口: chat()/stream()/embed()/health()
│   │   ├── OpenAiClient.java
│   │   ├── ClaudeClient.java
│   │   ├── GeminiClient.java
│   │   └── OllamaClient.java
│   ├── ResilienceDecorator.java     # 包 CircuitBreaker+Retry+TimeLimiter+Bulkhead
│   └── ProviderRouter.java          # 按 Agent 配置+熔断状态选主/备提供商
│
├── agent/                           # Agent 配置
│   ├── AgentController
│   ├── AgentService
│   ├── AgentRepository
│   ├── Agent.java                   # entity: 名称/prompt/providerRef(优先级链)/knowledgeRefs/toolRefs
│   └── dto/
│
├── conversation/                    # 对话引擎（SSE）
│   ├── ConversationController       # GET/POST /chat/stream 返回 SseEmitter
│   ├── ConversationService          # 组装上下文，调 ProviderRouter，逐 token 推送
│   ├── ConversationRepository
│   ├── Conversation.java            # 会话
│   ├── Message.java                 # 单条消息(角色/内容/耗时/token)
│   └── dto/
│
├── knowledge/                       # 知识库 RAG
│   ├── KnowledgeController
│   ├── KnowledgeService             # 上传/切分/向量化/索引
│   ├── DocumentRepository
│   ├── Document.java                # 文档元信息
│   ├── DocumentChunk.java           # 切分片段
│   ├── embedding/EmbeddingService   # 调 ProviderClient.embed()
│   └── retriever/RetrievalPort.java # 对外暴露检索接口（供 conversation 调用）
│
├── workflow/                        # 简版工作流
│   ├── WorkflowController
│   ├── WorkflowService
│   ├── WorkflowRepository
│   ├── Workflow.java                # entity: 节点定义(顺序链)
│   ├── WorkflowEngine.java          # 顺序节点执行器
│   └── node/                        # 节点类型: LLMNode / RetrievalNode / ToolNode / EndNode
│
└── mcp/                             # MCP 工具接入
    ├── McpController
    ├── McpService
    ├── McpServerRepository
    ├── McpServer.java               # entity: 名称/url/enabled/已发现 tools
    └── McpClientManager.java        # 用 MCP Java SDK 连接 Server、发现 tools、执行调用
```

**模块间解耦纪律**（来自 02 文档第 6/7 节）：
- 每个功能包自包含（自己的 controller/service/repo/entity/dto）。
- 跨包调用只走接口/事件：`conversation` 不 `@Autowired` `agent` 内部 service，而是接收 `Agent` 装配好的定义，经 `RetrievalPort` 查知识，经 `ProviderRouter` 调模型。
- `common` 禁止反向依赖任何业务包。

## 3. 前端结构（Vue 3 + Vite）

```
frontend/src
├── main.js
├── App.vue
├── router/                  # 路由：/chat /agents /knowledge /models /workflows /mcp /login
├── stores/                  # Pinia: auth(登录态), app(当前 agent)
├── api/                     # axios 封装，按模块分文件: agent.js / knowledge.js / chat.js ...
├── views/
│   ├── Login.vue
│   ├── Chat.vue             # 聊天界面，SSE 用 EventSource / fetch 读流
│   ├── AgentList.vue / AgentEdit.vue
│   ├── KnowledgeList.vue / KnowledgeUpload.vue
│   ├── ModelProvider.vue
│   ├── Workflow.vue
│   └── McpServer.vue
├── components/              # 复用的 UI 组件（消息气泡、Markdown 渲染、表单）
└── utils/                   # 请求、token 存储、SSE 解析
```

## 4. 后端关键依赖（pom.xml 摘要）

```xml
<!-- 基础 -->
<spring-boot-starter-parent>3.3.x</spring-boot-starter-parent>
<java.version>21</java.version>   <!-- 使用当前系统安装的 Java 21 -->

<dependencies>
  <!-- Web / 校验 /  actuator -->
  <dependency> spring-boot-starter-web </dependency>
  <dependency> spring-boot-starter-validation </dependency>
  <dependency> spring-boot-starter-actuator </dependency>

  <!-- 安全（登录+轻量权限） -->
  <dependency> spring-boot-starter-security </dependency>
  <dependency> io.jsonwebtoken:jjwt-api + jjwt-impl + jjwt-jackson </dependency>

  <!-- 数据：业务库 + 向量库 -->
  <dependency> spring-boot-starter-data-jpa </dependency>
  <dependency> com.mysql:mysql-connector-j </dependency>
  <dependency> org.postgresql:postgresql </dependency>
  <dependency> org.springframework.boot:spring-boot-starter-data-redis </dependency>
  <dependency> org.flywaydb:flyway-core </dependency>
  <dependency> org.flywaydb:flyway-database-postgresql </dependency>

  <!-- AI：LangChain4j（覆盖 4 家提供商 + MCP + pgvector） -->
  <dependency> dev.langchain4j:langchain4j-core:1.x </dependency>
  <dependency> dev.langchain4j:langchain4j-open-ai:1.x </dependency>
  <dependency> dev.langchain4j:langchain4j-anthropic:1.x </dependency>
  <dependency> dev.langchain4j:langchain4j-google-ai-gemini:1.x </dependency>
  <dependency> dev.langchain4j:langchain4j-ollama:1.x </dependency>
  <dependency> dev.langchain4j:langchain4j-mcp:1.x </dependency>
  <dependency> dev.langchain4j:langchain4j-pgvector:1.x </dependency>

  <!-- 容错（04 文档四件套） -->
  <dependency> io.github.resilience4j:resilience4j-spring-boot3 </dependency>
  <dependency> io.github.resilience4j:resilience4j-circuitbreaker </dependency>
  <dependency> io.github.resilience4j:resilience4j-retry </dependency>
  <dependency> io.github.resilience4j:resilience4j-bulkhead </dependency>
  <dependency> io.github.resilience4j:resilience4j-timelimiter </dependency>

  <!-- 减样板 / 文档 -->
  <dependency> org.projectlombok:lombok </dependency>
  <dependency> org.springdoc:springdoc-openapi-starter-webmvc-ui:2.x </dependency>

  <!-- 测试 -->
  <dependency> spring-boot-starter-test </dependency>
  <dependency> io.github.resilience4j:resilience4j-test </dependency>
</dependencies>
```

> 版本提示：Spring Boot 与 LangChain4j/Resilience4j 版本需对齐（用 Spring Boot 父 POM 管理）；LangChain4j 迭代快，先固定一个 1.x 稳定版再开发（见 02 文档第 7.4 节）。

## 6. 本地开发依赖（docker-compose.yml 摘要）

```yaml
services:
  mysql:      { image: mysql:8,      port: 3306, volume: mysql-data }
  redis:      { image: redis:7,      port: 6379, volume: redis-data }
  pgvector:   { image: pgvector/pgvector:pg17, port: 5432, volume: pg-data }
```
> 开发者本地 `docker compose up` 起这三个依赖即可跑后端，无需装数据库。

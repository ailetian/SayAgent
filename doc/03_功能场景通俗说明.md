# SayAgent 功能场景通俗说明

> 目的：用大白话讲清楚 SayAgent 是做什么的、在什么场景下用，供非技术同学或新成员快速理解。
> 文档版本：v1.0
> 日期：2026-07-18
> 关联文档：《01_功能需求文档.md》《02_技术选型文档.md》

---

## 1. 一句话定位

SayAgent 是一个**给团队自己用的"AI 员工制造厂"**——由一人搭建平台，团队内 50 人都能拥有自己的 AI 助手，且这些助手**看得懂公司文档、还能动手操作公司系统**。

---

## 2. 它解决什么痛点

平时用通用 AI（如 ChatGPT）有两个毛病：

1. **它不懂你们公司的事**：问"咱们年假怎么请"，它答不上来，因为没你们的制度文档。
2. **它动不了你们的系统**：问"帮我查客户 X 的订单"，它只能说"抱歉我查不了"。

SayAgent 专门补上这两点，是一个内部平台。

---

## 3. 六大功能，用大白话讲

| 功能 | 大白话 |
|---|---|
| **模型提供商管理** | 决定"用谁的大脑"：管理员在后台**手动添加**一个个模型——填名称、API 地址、秘钥、类型（OpenAI / Claude / Gemini / Ollama 等），配一次全公司共用 |
| **Agent 配置** | 造一个"AI 员工"：给它设人设和技能（是客服还是 HR 助理？看哪些知识库？能用哪些工具？），配好即生成一个可复用的助手 |
| **对话引擎** | 真正聊天的机制：用户打字，引擎把问题、上下文、知识、工具串起来调模型，再把回答像打字机一样流式吐出 |
| **知识库 RAG** | 让 AI 读懂你们的文件：上传手册/文档/PDF，系统自动切分转向量存储；有人问相关问题时，AI 先去知识库找内容再回答（"AI 懂公司事"的关键） |
| **简版工作流** | 把几步活儿串成自动流水线：如"读邮件 → 提取要点 → 生成摘要 → 发群里"，比单纯聊天更进一步，能替你跑固定流程 |
| **MCP 工具接入** | 让 AI 能"动手"：通过 MCP 连上内部系统（数据库、CRM、工单、内部 API），AI 能真去查数据、调接口、执行操作（"AI 动得了系统"的关键） |

---

## 4. 具体应用场景（50 人团队）

- **场景 A：全员制度问答助手**——上传员工手册/报销制度/IT 规范，新人问"年假怎么请、报销上限多少"，AI 秒答，不翻文档、不打扰 HR。
- **场景 B：会查系统的业务助手（MCP 价值）**——MCP 连上客户数据库，销售问"客户 X 最近下了几单、欠多少钱"，AI 直接查出来并总结，不用登后台导表。
- **场景 C：IT/HR 自助台**——常见流程（改密码、申请权限、请假规则）做成 Agent，员工自助问，解放人力。
- **场景 D：自动日报工作流**——简版工作流定时抓取竞品/数据源 → 总结要点 → 推送到群，一人配置全组受益。
- **场景 E：新人 Onboarding 伴侣**——把产品文档/架构图/FAQ 喂给"公司百事通"Agent，新人前两周问题基本都能答。

---

## 5. 一个完整例子串起来

> 你在 SayAgent 后台：选好模型（功能1）→ 建"HR 助理"Agent，挂上员工手册知识库、并授权查考勤系统（功能2+4+6）→ 同事问"我还有几天年假" → 对话引擎把问题丢给模型，模型先去知识库确认规则、再通过 MCP 查考勤库拿到天数，最后流式回复（功能3）。整个过程你只配置一次，50 个人天天用。

---

## 6. 一句话总结

**SayAgent = 让团队拥有"懂公司文档 + 能操作公司系统"的 AI 助手，而搭建和维护只需要你一个人。**

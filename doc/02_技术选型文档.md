# SayAgent 技术选型文档

> 项目定位：基于 Dify 思路、面向团队内部的简化版 AI Agent 平台
> 文档版本：v1.1（选型修订）
> 日期：2026-07-18
> 说明：经评估，最终定型由 Python FastAPI + React 修订为 **Spring Boot + Vue**，详见第 4 节。

## 1. 选型背景与约束

| 约束项 | 说明 |
|---|---|
| 开发资源 | 单人开发（全栈从 0 到上线） |
| 使用对象 | 团队内部 20-50 人 |
| 部署方式 | 本地部署（单租户、自托管） |
| 产品本质 | AI 逻辑密集型平台（RAG / Agent / MCP / 模型管理） |
| 评估维度 | 开发效率、生态成熟度、AI 领域 SDK 支持、运维复杂度 |

---

## 2. 候选方案对比

| 维度 | ① Spring Boot + Vue | ② Go + React | ③ Python FastAPI + React |
|---|---|---|---|
| **开发效率** | 中（Java 啰嗦，AI 逻辑要写大量胶水） | 中高（语言简洁，但 AI 部分要从零造） | **高（AI 领域最省力）** |
| **生态成熟度** | 企业级 CRUD 极成熟 | 后端/微服务成熟 | **AI 生态碾压性成熟** |
| **AI SDK 支持** | 弱（LangChain4j 落后） | 弱（基本只能裸调 API） | **最强（LangChain/LlamaIndex/openai/mcp 全有）** |
| **运维复杂度** | 中高（JVM 内存大、镜像大） | **最低（单二进制、极小镜像）** | 中（Python 环境管理，本地够用） |
| **MCP 接入** | Go/Java SDK 较新、样例少 | Go SDK 一般 | **官方 Python SDK 最完整** |
| **RAG 支持** | 需自研或借力 Python 服务 | 需自研 | **开箱即用（向量库/切分/嵌入）** |

---

## 3. 各方案细评

### ① Spring Boot + Vue
- **优势**：企业级稳健、Vue 上手快、类型安全、长期可维护性高。
- **劣势**：AI 是主战场，Java 的 AI 生态明显落后——LangChain4j 功能与社区远不及 Python；RAG、Agent、MCP 几乎都要自己封装。单人要把 AI 核心逻辑用 Java 重写，工作量巨大且易踩坑。
- **结论**：除非只做"套壳对话"，否则 AI 部分会严重拖慢进度。

### ② Go + React
- **优势**：编译快、单文件部署、镜像极小，本地运维最省心；并发性能强。
- **劣势**：AI 生态最薄弱，没有堪用的 LangChain 等价物，LLM 调用、RAG、Agent 编排、MCP 基本都得手写 HTTP 胶水。对 AI Agent 平台这种 AI 逻辑密集的产品，等于放弃现成轮子。
- **结论**：适合做高性能网关/中间件，不适合做 AI 平台核心。

### ③ Python FastAPI + React
- **优势**：
  - AI SDK 一站齐活：OpenAI/Anthropic 官方 SDK、LangChain、LlamaIndex、MCP Python SDK、sentence-transformers、各类向量库客户端全是原生一等公民。
  - FastAPI 开发极快，自带异步、自动 OpenAPI 文档，单人友好。
  - RAG 与 MCP 直接复用成熟库，需求文档中的 8 个必做模块几乎都能"拼装"实现。
  - 20-50 人本地部署，I/O 密集（LLM 调用是网络等待），GIL 不是瓶颈，性能完全够。
- **劣势**：Python 环境/依赖管理稍麻烦（用 Poetry/uv 可缓解），镜像比 Go 大；严格类型与编译期检查弱于 Java/Go。
- **结论**：最契合本项目的方案。

## 4. 最终定型结论（修订）

> **选定方案：Spring Boot + Vue**

**决策理由（一句话）**：单人开发企业级后端，Spring Boot 的"出厂即规范"（DI、事务、安全、迁移、监控）能显著降低工程化踩坑成本，工程严谨度优先于 AI 生态的拼装便利；AI 能力通过 LangChain4j / MCP Java SDK 补齐，对本项目规模可行。

**架构隐含约定**：
- 后端 Spring Boot 包揽全部能力：登录/权限、模型管理、Agent、RAG、MCP、对话日志。
- 前端 Vue（Element Plus / Naive UI）做配置页 + 聊天 UI。
- 前后端通过 SpringDoc 自动生成的 OpenAPI 契约对接。
- 构建用 Gradle/Maven，部署用 docker-compose。
- **对第 2/3 节对比的说明**：原对比中 FastAPI 在"AI 生态"占优，但本决策以"工程化稳健 + 单人可控"为先，AI 短板用第 6 节的方案兜底。

## 5. 与功能需求文档的对应关系

本选型服务于《功能需求文档.md》中确认的范围：
- **必须做 8 项**：登录+权限、模型管理、Agent 配置、知识库+RAG、聊天 Web UI+API、对话日志、单租户本地部署、MCP 集成。
- **砍掉 6 项**：可视化 Workflow 画布、插件市场、嵌入发布、高级 LLMOps、多租户/计费、知识管道评测台。

## 6. AI 能力在 Java 侧的落地方案（关键补全）

针对第 2/3 节指出的"Java AI 生态弱"短板，采用以下组件兜底，确保 8 个必做模块均可实现：

| 能力 | Java 侧推荐方案 | 备注 |
|---|---|---|
| LLM 调用 / Agent | **LangChain4j** | 已支持 OpenAI、Anthropic、Ollama 等主流模型，提供 ChatMemory、Tool、RAG 高层 API |
| MCP 集成 | **LangChain4j MCP / 官方 MCP Java SDK** | 支持以 client 连接 MCP Server，自动发现 tools；满足"必须做第 8 项" |
| RAG / 向量检索 | LangChain4j + **pgvector / Milvus / Redis** | 文档切分、嵌入、向量检索均有封装，无需自研 |
| 嵌入模型 | LangChain4j EmbeddingStore + Ollama/OpenAI embeddings | 复用模型管理配置的密钥 |
| 参数校验 | Spring Validation（Bean Validation） | 比 Pydantic 更标准化 |
| 数据库 / 迁移 | JPA/Hibernate + **Flyway/Liquibase** | 企业级数据访问开箱即用 |
| 安全 | Spring Security + JWT | 覆盖"基础登录+轻量权限" |
| 可观测 | Actuator + Micrometer | 覆盖基础日志/监控，无需额外拼装 |

**风险与缓解**：
- LangChain4j 迭代快、个别高级特性落后于 Python → 锁定版本，优先用稳定 API；复杂编排必要时用 HTTP 直连 LLM。
- MCP Java 样例较少 → 以官方 MCP Java SDK 为主，先接 1-2 个内部 MCP Server 验证链路。

## 7. Python 开发者上手 Spring Boot 的最小路径（开发者仅会 Python）

> 前提：开发者当前只会 Python，选择从零学 Java/Spring Boot 实现本项目。目标不是"精通 Java"，而是"够用即可跑通 MVP"。

### 7.1 学习分阶段（估算 1.5-2 周可动手做 MVP）
| 阶段 | 内容 | 时间 | 重点 |
|---|---|---|---|
| 0 | Java 21 速成 | 1-2 天 | 只学 CRUD 够用：类/方法、record、var、Optional、List/Map、异常、基础 stream。跳过分型/JVM 调优 |
| 1 | Spring Boot Hello World | 2-3 天 | 用 start.spring.io 脚手架；理解 @RestController / @Service / @Repository / @Autowired；跑通 JPA + H2 的 CRUD |
| 2 | 安全与配置 | 1-2 天 | Spring Security + JWT 登录；application.yml；Flyway 建表 |
| 3 | 接 AI | 2-3 天 | LangChain4j 调通一个 chat 接口 + ChatMemory；再接 MCP Java SDK 连一个内部 Server |
| 4 | RAG | 2-3 天 | LangChain4j + pgvector 文档检索 |

### 7.2 降低 Java 学习面的工具与约定
- **脚手架**：用 start.spring.io 生成，不手写 Maven 复杂配置。
- **构建**：用 Maven（比 Gradle 对初学者更直白）；IDE 用 IntelliJ IDEA Community（免费且 Java 体验最好）。
- **减样板**：用 Lombok + record，避免手写 getter/setter。
- **写码方式**：让 AI 助手生成 Spring 样板代码，你负责审读与组装（你会读程序，迁移成本主要在"写"不在"懂"）。
- **严格守 MVP 范围**：不碰微服务 / DDD / 复杂抽象，单体应用一把梭。

### 7.3 Python 开发者易踩的坑
- LLM 调用是阻塞 I/O，用 WebClient / @Async，避免卡住请求线程。
- 不要用 `null` 满天飞，用 Optional / 注解做空安全。
- 测试习惯延续：早期写 JUnit（对应 pytest），别等最后补。
- 版本锁定：LangChain4j / MCP Java SDK 迭代快，固定版本再开发。

### 7.4 风险兜底
- 若某 AI 高级特性 LangChain4j 不支持，降级为 HTTP 直连 LLM API（你会 Python，可先写原型验证逻辑，再翻成 Java）。
- MCP 首版先接 1-2 个内部 Server 验证链路，不在 Java 侧造复杂编排。

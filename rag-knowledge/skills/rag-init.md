# /rag-init — RAG 项目搭建前引导

> 在新 RAG 项目目录下触发。引导你完成场景分析 → 架构推荐 → 验收标准制定。
> 全程交互式问答，最终输出一份可存档的方案文档。

---

## 阶段1：场景分析

逐项询问用户，每次只问一个问题，等用户回答后再继续。

### Q1：知识库用途

```
这个知识库主要给谁用、用来查什么？

[1] 内部规章制度问答 — 员工查公司手册、考勤、薪酬等
[2] 客服知识库 — 客户问产品功能、退换货政策等
[3] 技术文档问答 — 开发文档、API文档、运维手册
[4] 多场景混合 — 以上两种或以上
[5] 其他（请描述）
```

### Q2：知识库体量

```
预计有多少文档？

[1] 小型 — <100 篇，总字数 <10 万字
[2] 中型 — 100~1000 篇
[3] 大型 — 1000~10000 篇
[4] 超大型 — >10000 篇，可能需要分布式方案
```

### Q3：查询类型

```
用户主要会怎么提问？

[1] 精确查找 — "年假几天""加班费怎么算"，答案明确在某段文档里
[2] 语义理解 — "怎么提升工作效率"，需要综合多处信息
[3] 两者都有
```

---

## 阶段2：质量要求

### Q4：准确率要求

```
回答错了的后果有多严重？

[1] 宽松 — 聊胜于无，辅助人工参考
[2] 标准 — 允许偶尔出错，用户可容忍
[3] 严格 — 错误回答会造成业务损失或合规风险
```

### Q5：并发量

```
预计同时有多少人使用？

[1] 低 — <10 QPS，内部工具级别
[2] 中 — 10~100 QPS，团队/部门级别
[3] 高 — >100 QPS，对外服务级别
```

### Q6：文档更新频率

```
文档会定期更新吗？

[1] 几乎不变 — 一次性导入，长期使用
[2] 月度/季度更新 — 定期有少量变更
[3] 频繁更新 — 周级别甚至实时更新
```

---

## 阶段2.5：答案→推荐参数速查（AI参考，不展示给用户）

根据 Q1~Q6 的答案组合，快速匹配推荐参数：

| 场景 | Q1 | Q2 | Q3 | chunk_size | 检索引擎 | Rerank | Rewrite |
|------|----|----|-----|-----------|---------|--------|---------|
| 内部规章 | 1 | 1~2 | 1 | 800~1000 | 纯向量(小)/混合(中) | 否 | 建议 |
| 客服知识库 | 2 | 2~3 | 3 | 500~800 | 混合 | 大文档量时加 | 建议 |
| 技术文档 | 3 | 2~3 | 3 | 500~800 | 混合 | 大文档量时加 | 建议 |
| 多场景 | 4 | 3~4 | 3 | 按主体文档类型 | 混合+Rerank | 建议 | 建议 |

| Q4(准确率) | 对应等级 | 验收标准等级 |
|-----------|---------|-------------|
| 1 宽松 | 内部工具 | 见 evaluation_standards.md "内部工具"列 |
| 2 标准 | 业务系统 | 见 evaluation_standards.md "业务系统"列 |
| 3 严格 | 对外服务 | 见 evaluation_standards.md "对外服务"列 |

| Q5(并发) | 向量库推荐 |
|---------|-----------|
| 低 (<10 QPS) | Chroma（单机） |
| 中 (10~100) | Qdrant / Weaviate |
| 高 (>100) | Milvus（分布式） |

| Q6(更新频率) | 索引更新策略 |
|-------------|-------------|
| 几乎不变 | 一次性全量导入 |
| 月度/季度 | 定期全量重建（脚本自动化） |
| 频繁更新 | 增量 upsert（需要文档变更追踪） |

## 阶段3：方案输出

根据上述映射表，匹配后输出以下内容：

### 3.1 架构推荐

```
推荐方案：

切块策略：
  - chunk_size: [根据场景推荐值]
  - chunk_overlap: [根据场景推荐值]
  - 切分方式: [Markdown标题切 / 递归字符切 / 两者结合]

检索引擎：
  - [纯向量 / 混合(BM25+向量) / 混合+Rerank]
  - 原因: [一句话解释]

是否推荐 Query Rewriting: [是/否]
是否推荐多轮对话支持: [是/否]
是否推荐 Rerank: [是/否]
```

### 3.2 技术选型

```
Embedding 模型: [推荐模型名]
向量库: [Chroma(小)/Milvus(大)/Qdrant(中)]
LLM: [根据场景推荐]
```

### 3.3 验收标准（推荐值，可调整）

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 召回率@5 | [值] | 正确答案至少出现在 top5 中 |
| MRR | [值] | 最相关文档排在第一位的概率 |
| Faithfulness | [值] | 回答不能编造文档中没有的信息 |
| Answer Relevancy | [值] | 回答真正回应用户问题 |
| 拒答率 | [值] | 不知道时不能说不知道 |
| P95延迟 | [值] | 95%请求在此时间内返回 |

详细指标说明见 `rag-knowledge/docs/rag_evaluation_standards.md`。

### 3.4 推荐的项目结构

```
your-rag-project/
├── data/                  ← 原始文档放这里
├── main.py                ← 主入口
├── config.py              ← 配置参数
├── benchmark.py           ← 评测脚本（可从 snippets 复制）
├── chroma_db/             ← 向量库存放目录
└── requirements.txt
```

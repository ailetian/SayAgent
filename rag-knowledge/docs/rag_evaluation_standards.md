# RAG 评测标准

> 定义每个指标的含义、计算方法、推荐目标值
> 评测工具推荐 RAGAS，成熟度最高

---

## 1. 检索质量指标

### 1.1 召回率@K（Recall@K）

```
大白话：标准答案里的关键信息，检索结果里有没有？

计算：命中的关键词数 / 应该出现的关键词总数

推荐目标：
  精确查找类: ≥ 90%
  语义理解类: ≥ 80%
```

### 1.2 MRR（Mean Reciprocal Rank）

```
大白话：用户最想看的那个文档，排在第几位？

计算：对于每个查询，找到第一个相关文档的排名 rank
      MRR = (1/rank₁ + 1/rank₂ + ... + 1/rankₙ) / n

示例：
  查询1: 最相关文档在第1位 → 得分 1/1 = 1.0
  查询2: 最相关文档在第3位 → 得分 1/3 = 0.33
  查询3: 最相关文档在第2位 → 得分 1/2 = 0.50
  MRR = (1.0 + 0.33 + 0.50) / 3 = 0.61

推荐目标：
  内部工具: ≥ 0.75
  业务系统: ≥ 0.85
  对外服务: ≥ 0.90
```

### 1.3 NDCG@K（Normalized Discounted Cumulative Gain）

```
大白话：排前面的都是相关的吗？最相关的排最前面了吗？

不展开公式，一句话：NDCG 越接近 1 表示排序越理想。

推荐目标：
  通用: ≥ 0.80
```

## 2. 生成质量指标（RAGAS）

### 2.1 Faithfulness（忠实度）

```
大白话：回答有没有编造文档里没有的东西？

计算：将回答拆成多个"断言"，逐个检查是否能在检索到的文档中找到支撑

推荐目标：
  内部工具: ≥ 80%
  业务系统: ≥ 85%
  对外服务: ≥ 90%
```

### 2.2 Answer Relevancy（答案相关性）

```
大白话：回答是否真的回应了用户的问题？有没有跑题？

计算：从回答中反推问题，看反推的问题和原问题有多接近

推荐目标：
  内部工具: ≥ 75%
  业务系统: ≥ 80%
  对外服务: ≥ 85%
```

### 2.3 Context Precision（上下文精度）

```
大白话：检索到的文档里，有多少是真正有用的？有没有检索到一堆无关内容？

推荐目标：
  通用: ≥ 85%
```

### 2.4 Context Recall（上下文召回率）

```
大白话：回答所需的信息，检索结果里都覆盖了吗？

推荐目标：
  通用: ≥ 85%
```

## 3. 安全指标

### 3.1 拒答率

```
大白话：检索结果不够好时，系统有没有老实说"不知道"而不是硬编？

计算：不该回答的问题中，系统正确拒答的比例

推荐目标：
  内部工具: ≤ 10%（允许偶尔多答）
  业务系统: ≤ 5%
  对外服务: ≤ 3%（不能胡说）
```

### 3.2 幻觉率

```
大白话：回答里有多少是文档里根本没有的信息？

和 Faithfulness 互补：Faithfulness 越高 = 幻觉率越低

推荐目标：
  ≤ 10%
```

## 4. 性能指标

### 4.1 延迟

```
P50: 50% 的请求在此时间内完成
P95: 95% 的请求在此时间内完成（这是用户实际感受到的"最慢"）
P99: 异常值排除后的上限

推荐目标：
  内部工具: P95 ≤ 5s
  业务系统: P95 ≤ 3s
  对外服务: P95 ≤ 1s
```

### 4.2 吞吐量

```
最大 QPS：系统能稳定支撑的每秒查询数

目标：根据 Q5 的回答动态设定
  低并发: ≥ 5 QPS
  中并发: ≥ 50 QPS
  高并发: ≥ 200 QPS
```

## 6. 测试用例设计原则

1. **每个文档段落至少 1 条测试用例**，确保覆盖完整
2. **包含 3 种查询类型**：精确查询 / 语义查询（口语化） / 综合查询
3. **包含边界测试**：问文档里没有的内容 → 应该拒答
4. **关键词必须对齐文档原文格式**：文档写"5 天"，关键词不能写"5天"
